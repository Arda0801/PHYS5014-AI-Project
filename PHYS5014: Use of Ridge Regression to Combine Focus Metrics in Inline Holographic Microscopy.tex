\begin{abstract}
In inline holographic microscopy, the correct numerical refocus distance must be determined computationally, as the sample-to-camera distance is unknown. Seven focus metrics are computed at 180 depth values across 676 holograms spanning five sample types: bee wing, ipomoea leaf, lillium anther, paramecium stained, and a USAF resolution target. Used individually, these metrics achieve a maximum fraction correct of 0.675 at a tolerance of 0.1\,mm (\texttt{sobel\_variance}). This work investigates whether machine learning can combine these seven metrics into a single, more reliable focus measure. Two models are trained and evaluated: Ridge regression, which learns a linear weighted combination, and a Multi-Layer Perceptron (MLP), which captures non-linear interactions between metrics. The Ridge model achieves a fraction correct of 0.676, a marginal improvement over the best individual metric. The MLP achieves 0.757, an improvement of 8.2 percentage points over the best individual metric. Both models achieve perfect performance on lillium anther samples but struggle with paramecium stained, where Ridge achieves only 0.250 compared to the MLP's 0.607. The superior performance of the MLP suggests that the relationship between focus metrics is not purely linear. This effect is most evident for paramecium stained samples, where the MLP substantially outperforms Ridge regression.
\end{abstract}

\section{The Big Picture}
The physical problem is autofocus in inline holographic microscopy: given a hologram of an unknown sample, find the correct numerical refocus distance. Seven different focus metrics are computed at 200 depth values for each hologram. The original dataset contains 750 holograms, of which 676 remain after applying the depth-offset filtering described in Section \ref{prepare}, spanning five biological and optical sample types. Each metric provides a partial, noisy signal about which depth is in focus, and no single metric reliably identifies the correct depth across all sample types and conditions.

Success is defined using the \texttt{fraction\_correct} metric: the proportion of test images for which the model's predicted best-focus depth falls within a tolerance window of the manually-determined ground truth depth. The primary tolerance used is 0.1 mm, which corresponds to ten depth steps of 10 microns each. A secondary evaluation is also performed at tolerances of 0.05, 0.2, and 0.5 mm to give a fuller picture of model precision. The primary goal is to determine whether a machine-learning model can outperform the best individual focus metric.

\section{Get Data}

Dataset is provided as a Python pickle file (\texttt{focus\_score\_curves\_dataset.pkl})\cite{Ridge} and is loaded using the \texttt{load\_focus\_data} helper function from \texttt{helpers.py}.\cite{Helpers}  The dataset contains:

\begin{itemize}
    \item\textbf{scores:} An array of shape (750 images, 200 depths, 7 metrics) containing the raw focus metric values.
    \item\textbf{depths:} The 200 numerical refocus distances in millimetres, spanning 0 to 2 mm in 10 micron steps.
    \item\textbf{true\_depths:} The manually-determined ground truth focus depth for each image (in mm).
    \item\textbf{image\_types:} The sample type label for each image (paramecium, lilium, bee wing, ipomoea, or USAF target).
    \item\textbf{metrics:} The names of the seven focus metrics.
\end{itemize}

The seven metrics can be broadly grouped by what image property they measure. \texttt{sobel}, \texttt{sobel\_variance}, \texttt{brenner}, and \texttt{dark\_focus} are gradient-based metrics that respond to sharp edges and high-frequency image content. \texttt{norm\_var} measures the normalised variance of pixel intensities. \texttt{sum} sums pixel values across the image, and \texttt{peak} records the maximum pixel value. Further details are available in the PyHoloscope documentation.\cite{Helpers} \cite{Pyholoscope}

A pristine test set is isolated before any preprocessing or model fitting. The data is split at the image level and all 200 depth values for a given image go entirely into either the training set or the test set, never both. This is critical: splitting at the depth level would allow the same image to appear in both sets, causing data leakage and falsely inflating test performance. 80\% of images are used for training (540 images) and 20\% for testing (136 images). Stratification by \texttt{image\_types} ensures each sample type is proportionally represented in both sets, so the test set fairly represents all conditions the model will encounter. \cite{Textbook}

\begin{lstlisting}[language=Python, caption={Snippet of code from $ridge\_regression.py$ \cite{Ridge}}, basicstyle=\ttfamily\small, frame=single, breaklines=true]
    train_idx, test_idx = train_test_split(
    image_indices, test_size=0.2, random_state=42, stratify=data.image_types)
\end{lstlisting}

    \item All metrics produce noisy, unreliable outputs at distances below approximately 0.2\,mm, because holographic reconstruction is poor at very short range. This motivates the depth offset applied in Section~\ref{prepare}.

    \item For many images, multiple metrics simultaneously show local minima near the true depth, suggesting that a learned combination could outperform any single metric. This can be seen in Figures~\ref{fig:single_ridge} and~\ref{fig:single_MLP}.
\end{itemize}

\section{Prepare} \label{prepare}

\textbf{Depth offset:} The first 20 depth values (covering 0 to 0.2 mm) are removed by passing \texttt{offset=20} to \texttt{load\_focus\_data}. In this region, all metrics produce noisy, unreliable outputs because holograms do not reconstruct well at very short distances. Removing this region improves both training stability and evaluation accuracy. This reduces the depth range from 200 to 180 values per image. This filtering caused the dataset to change from 750 to 676 holograms and these were used for all the subsequent training and evaluation which can be seen in Table \ref{tab:preprocessing}.

\textbf{Per-image normalisation:} Each of the seven metrics is independently normalised to the range [0, 1] within each image:

\begin{lstlisting}[language=Python, caption={Snippet of code from $ridge\_regression.py$ \cite{Ridge}}, basicstyle=\ttfamily\small, frame=single, breaklines=true]
s_min = scores.min(axis=1, keepdims=True) 
s_max = scores.max(axis=1, keepdims=True)  
scores_norm = (scores - s_min) / (s_max - s_min + 1e-8)
\end{lstlisting}

This is done per-image rather than globally because the absolute values of metrics vary considerably between images depending on sample brightness and contrast. Per-image normalisation ensures the model responds to the shape of the curve where the metric is low or high relative to its own range, rather than its absolute magnitude. The small epsilon (1e-8) prevents division by zero in edge cases.

\textbf{Gaussian target labels:} Ridge regression requires a scalar target value for every (image, depth) data point. A Gaussian-shaped soft label is constructed for each image, centred on its true depth: \cite{Ridge}

\begin{equation}
    t(d) = \exp\!\left(-\frac{1}{2}\left(\frac{d - d_{\text{true}}}{\sigma}\right)^2\right)
\end{equation}

This assigns a target value of 1.0 at the true focus depth, falling smoothly to 0.0 at depths far from focus. A sigma of 0.1 mm is used, which is wide enough for the model to learn from neighbouring depths but narrow enough to produce a precise minimum. The result is a well-posed regression problem: the model learns to predict high values near focus and low values far from it.

\textbf{StandardScaler:} After per-image normalisation, a StandardScaler from sklearn is applied to standardise each of the seven features to zero mean and unit variance across the training set. This is important for Ridge regression because the L2 penalty treats all features equally without standardisation, a feature with a slightly larger scale would be penalised more heavily than intended. The scaler is fit only on the training set and applied (without refitting) to the test set to prevent data leakage. \cite{Scikit_Standard}

\textbf{Dataset construction:} The data is flattened from shape (N\_images, 180 depths, 7 metrics) into shape (N\_images × 180, 7) for sklearn compatibility, with corresponding Gaussian targets of shape (N\_images × 180,). This produces approximately 108,000 training samples.

\section{Train}

\subsection*{Ridge Regression}

A Ridge regression model is trained using sklearn's \texttt{Ridge} class with regularisation strength \texttt{alpha = 1.0}:\cite{Scikit_Ridge}

\begin{lstlisting}[language=Python, caption={Snippet from ridge\_regression.py \cite{Ridge}}, basicstyle=\ttfamily\small, frame=single, breaklines=true]
model = Ridge(alpha=1.0)
model.fit(X_train_scaled, y_train)
\end{lstlisting}

Ridge regression finds the weight vector $\mathbf{w}$ and bias $b$ that minimise:

\begin{equation}
    \mathcal{L}_{\text{Ridge}} = \frac{1}{N}\sum_{i=1}^{N}\left(\hat{y}_i - y_i\right)^2 + \alpha\,\|\mathbf{w}\|^2
    \label{eq:ridge}
\end{equation}

The first term is the mean squared error between the predicted and Gaussian target values. The second term is the L2 penalty: $\alpha$ times the sum of squared weights. This penalty discourages any single metric from receiving a disproportionately large weight, which is important given that the seven metrics measure overlapping properties of the same image. Unlike the MLP described below, Ridge regression has a closed-form analytical solution --- sklearn solves Equation~\ref{eq:ridge} in a single linear algebra step, making training instantaneous and fully deterministic.\cite{Scikit_Ridge}

\subsection*{Multi-Layer Perceptron}

A Multi-Layer Perceptron (MLP) is trained as a more flexible alternative, capable of capturing non-linear interactions between metrics. The network is intentionally small because only seven input features are available and the dataset size is modest. Larger networks were unlikely to provide substantial benefit and would increase the risk of overfitting. The architecture consists of three fully connected layers:

\begin{itemize}
    \item \textbf{Input layer:} 7 neurons, one per focus metric at a single depth
    \item \textbf{Hidden layer 1:} 32 neurons with ReLU activation
    \item \textbf{Hidden layer 2:} 16 neurons with ReLU activation
    \item \textbf{Output layer:} 1 neuron, producing a single focus score for that depth
\end{itemize}

The network is applied independently to each (image, depth) pair, treating depth as a simple index rather than a continuous input variable. Rather than Gaussian target labels, the MLP is trained using a margin ranking loss. For each image, the loss penalises any configuration in which the predicted score at the true focus depth is not sufficiently lower than all other depths:\cite{Pytorch_Machine}

\begin{equation}
    \mathcal{L}_{\text{MLP}} = \frac{1}{N}\sum_{i=1}^{N} \frac{1}{D}\sum_{d=1}^{D} \max\!\left(0,\; m + s_i^{(d_{\text{true}})} - s_i^{(d)}\right)
    \label{eq:margin}
\end{equation}

where $s_i^{(d)}$ is the model's predicted score for image $i$ at depth $d$, $d_{\text{true}}$ is the true focus depth index, and $m = 0.2$ is the margin. The $\max(0, \cdot)$ clamp means the loss is zero when the true depth already scores lower than depth $d$ by at least $m$, and positive only when this condition is violated.

The model is trained for 150 epochs using the Adam optimiser with learning rate $10^{-3}$\cite{Adam}. The training loss decreases smoothly from 0.2587 at epoch 0 to 0.0353 at epoch 135, confirming stable convergence throughout training (Figure~\ref{fig:training_loss}). No sudden jumps or plateauing are observed, indicating that the learning rate and architecture are well-suited to the problem.

Performance is flat and equal across $\alpha \in \{0.01, 0.1, 1.0\}$, then degrades monotonically at higher values. This indicates the model is insensitive to the exact level of regularisation over a broad range but deteriorates when the penalty is strong enough to suppress the largest weights ($\alpha = 100.0$ reduces the dominant \texttt{norm\_var} weight from $+0.788$ to $+0.153$, effectively discarding the signal it carries). The value \texttt{alpha = 1.0} is used for the final model as it is the most interpretable choice within the optimal range.

\textbf{Ridge: Gaussian width.} The $\sigma$ parameter of the Gaussian target is set to 0.1\,mm, corresponding to ten depth steps. This ensures that the immediate neighbourhood of the true depth also receives high target values, reducing sensitivity to the discrete sampling of the depth axis. A smaller $\sigma$ (e.g.\ 0.05\,mm) would create sharper, more demanding targets; a larger $\sigma$ (e.g.\ 0.2\,mm) would be easier to fit but may produce broader output curves with less precise minima.

\textbf{MLP: margin and learning rate.} The margin $m = 0.2$ in Equation~\ref{eq:margin} is set to twice the primary evaluation tolerance of 0.1\,mm, so the model is trained to separate focus from non-focus by a margin that exceeds the measurement precision. The learning rate of $10^{-3}$ is the standard default for Adam and is consistent with the smooth convergence observed in training, where the loss decreased from 0.2587 at epoch 0 to 0.0353 at epoch 135.

\textbf{Depth offset.} Both models use \texttt{offset = 20}, removing the first 20 depth steps (0 to 0.2\,mm). This is motivated by the data exploration in Section~3, where all seven metrics were observed to produce unreliable outputs in this region.

A systematic search over $\sigma$ and the MLP margin using cross-validation on the training set would be a natural extension of this work, as would training separate models per sample type --- particularly for paramecium stained, which both models handle poorly.

The Ridge model provides only a marginal improvement over \texttt{sobel\_variance}, and only at certain tolerances: it outperforms at 0.10\,mm (0.676 vs 0.675) and 0.50\,mm (0.831 vs 0.830), but underperforms at 0.05\,mm (0.566 vs 0.604) and 0.20\,mm (0.735 vs 0.743). This consistent gap across all tolerances strongly suggests that non-linear interactions between the metrics carry meaningful predictive signal that a linear model cannot exploit.

Bee wing and ipomoea leaf are intermediate; the MLP matches or exceeds Ridge on both. Future work should repeat training with multiple random seeds and report the mean and standard deviation of performance.

\textbf{Learned weights (Ridge).} The learned weights of the Ridge model at $\alpha = 1.0$ are shown in Figure~\ref{fig:learned_weights} and Table~\ref{tab:weights}. The two largest-magnitude weights are assigned to \texttt{norm\_var} ($+0.788$) and \texttt{sum} ($-0.746$), despite both metrics performing at chance level individually (0.059). Conversely, \texttt{sobel\_variance}, the best individual metric, receives only $-0.083$, and \texttt{peak} is effectively ignored ($-0.004$). This counter-intuitive pattern is characteristic of Ridge regression with correlated inputs: the gradient-based metrics (\texttt{sobel}, \texttt{sobel\_variance}, \texttt{brenner}) are mutually correlated and so provide diminishing marginal information; the model redistributes weight towards the structurally different \texttt{norm\_var} and \texttt{sum} metrics, which may encode complementary information not captured by the gradient-based metrics. That \texttt{norm\_var} alone scores 0.059 but receives the largest positive weight illustrates that individual metric performance under \texttt{argmin} is not a reliable guide to the incremental value a metric adds within a combination.

\textbf{Single-image curve inspection.} Figures~\ref{fig:single_ridge} and~\ref{fig:single_MLP} show the combined metric output alongside the seven raw normalised metric curves for one bee wing test image. \textbf{Limitations.} The Ridge model provides no meaningful improvement over the best individual metric and is unable to capture non-linear interactions. Both models struggle with paramecium stained samples, though the MLP substantially mitigates this. The ground truth depths were determined manually and carry inherent subjectivity for three-dimensional samples, placing an upper bound on achievable performance. MLP results are subject to run-to-run variability from random initialisation. The filtering step reduced the dataset from 750 to 676 holograms. Future work could investigate alternative target-generation methods that remain valid near reconstruction boundaries, allowing a larger fraction of the available data to be retained. Given more time, training separate models per sample type, running the MLP multiple times to report mean and standard deviation, and exploring larger architectures would be the most productive next steps.

\section{Launch}

To use the trained model on new holographic data, the same preprocessing pipeline must be applied in the same order: remove the initial 20 depth values, apply per-image normalisation, apply the same \texttt{StandardScaler} (already fit on training data), and then call \texttt{model.predict()}. For the Ridge model, the output is negated so that the minimum corresponds to the predicted focus depth, matching the convention used by fraction\_correct.

\begin{lstlisting}[language=Python, caption={Example code for preprocessing and predicting for launch}, basicstyle=\ttfamily\small, frame=single, breaklines=true]
# Preprocessing new data
new_scores_norm = normalise_per_image(new_scores[:, 20:, :])
new_scores_flat = new_scores_norm.reshape(-1, 7)
new_scores_scaled = scaler.transform(new_scores_flat)   # use the already-fitted scaler

# Predict and find best focus depth
predictions = model.predict(new_scores_scaled).reshape(num_new_images, -1)
best_focus_indices = np.argmax(predictions, axis=1)   # highest prediction = best focus
best_focus_depths = data.depths[best_focus_indices]
\end{lstlisting}

For continuous monitoring, \texttt{fraction\_correct} should be evaluated periodically on new labelled images as they become available. If performance degrades (for example when imaging a new sample type or after instrument recalibration) the model should be retrained on an expanded dataset that includes the new data. Because Ridge regression trains in milliseconds, retraining is cheap. The \texttt{alpha} and \texttt{sigma} hyperparameters should be re-validated whenever the training set changes substantially, as the optimal values may shift with a different data distribution.

# Identical to the MLP version — split at image level, stratify by type.

def normalise_per_image(scores):
    s = scores.copy()
    s_min = s.min(axis=1, keepdims=True)
    s_max = s.max(axis=1, keepdims=True)
    s = (s - s_min) / (s_max - s_min + 1e-8)
    return s

train_scores_norm = normalise_per_image(train_scores)
test_scores_norm  = normalise_per_image(test_scores)

# ---Build Gausian Target Model----------------------------------------------------------------------
# This is the key difference from the MLP version. Because sklearn's Ridge
# regression is a standard supervised learning model, it needs a target value
# (a label) for every single data point.
#
# Each "data point" here is one (image, depth) pair. The input is 7 metric
# values. The target is a number representing "how in-focus is this depth?"
#
# We use a Gaussian centred on the true depth:
#   - At the true depth:      target ≈ 1.0  (very in-focus)
#   - Far from true depth:    target ≈ 0.0  (out of focus)
#
# The model then learns to predict these Gaussian values from the 7 metrics.
# At test time, we find the depth where the model's output is highest. That
# is our focus prediction. (Note: unlike the MLP which predicts LOW=focused,
# here HIGH=focused because the Gaussian peaks at the true depth. We negate
# the output before passing to fraction_correct which expects LOW=focused.)
#
# sigma controls the width of the Gaussian. A smaller sigma (e.g. 0.05) makes
# the target very sharp and precise — only depths very close to the true depth
# get a high label. A larger sigma (e.g. 0.2) is more forgiving and easier to
# learn, but may produce broader, less precise output curves.

def gaussian_target(depths, true_depth, sigma=0.1):
    return np.exp(-0.5 * ((depths - true_depth) / sigma) ** 2)

def build_dataset(scores_norm, true_depths_mm, depths_array, sigma=0.1):
    num_images, num_depths, num_metrics = scores_norm.shape
    X_list = []
    y_list = []

    for i in range(num_images):
        X_list.append(scores_norm[i])                                 
        y_list.append(gaussian_target(depths_array, true_depths_mm[i], sigma))
    X = np.vstack(X_list)  
    y = np.hstack(y_list)   
    return X, y

X_train, y_train = build_dataset(train_scores_norm, train_depths, data.depths, sigma=0.1)
X_test,  y_test  = build_dataset(test_scores_norm,  test_depths,  data.depths, sigma=0.1)

print(f"\nTraining set shape: X={X_train.shape}, y={y_train.shape}")
print(f"Test set shape:     X={X_test.shape},  y={y_test.shape}")

# ---Ridge Regression ----------------------------------------------------------------
# Ridge regression is sensitive to the scale of features even after per-image
# normalisation, because the regularisation penalty treats all features equally.
# StandardScaler rescales each of the 7 features to have mean=0 and std=1
# across all training samples. We fit the scaler ONLY on training data and
# then apply the same transformation to test data, never fit on test data,
# as that would be data leakage.

scaler  = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train) 
X_test_scaled  = scaler.transform(X_test)     

# ---Train the Ridge Regression model----------------------------------------------------------------
# Ridge regression is linear regression with L2 regularisation. This means
# it adds a penalty to the loss function that discourages large weights:
#
# The alpha parameter controls how strong the regularisation is:
#   - alpha=0:    pure linear regression, no regularisation (can overfit)
#   - alpha=1:    mild regularisation (good default)
#   - alpha=100:  strong regularisation (weights are pushed towards zero)
#
# Regularisation helps when the 7 metrics are correlated with each other. 
# Without it, the model might assign very large positive weight
# to one metric and equally large negative weight to a correlated one,
# which is numerically unstable and generalises poorly.

print("\nTraining Ridge Regression model...")

model = Ridge(alpha=1.0)
model.fit(X_train_scaled, y_train)

    print(f"  {metric:<20s}: {weight:+.4f}")
print(f"  {'bias':<20s}: {model.intercept_:+.4f}")

# The weights tells how much each metric contributes to the combined score.
# A large positive weight means that metric strongly indicates focus when high.
# A near-zero weight means that metric is being mostly ignored.

# --- Generate predictions on the test set ----------------------------------------------------------------
# At test time, we run the model on each (image, depth) pair and reshape the
# outputs back into curves of shape (num_images, num_depths).
#
# The model outputs HIGH values where it thinks the image is in focus because of the Gaussian target.

predicted_curves_pos = y_pred.reshape(len(test_idx), data.num_depths)

test_scores  = data.scores[test_idx]
train_depths = data.true_depths[train_idx]
test_depths  = data.true_depths[test_idx]

print(f"\nTrain images: {len(train_idx)}, Test images: {len(test_idx)}")

# -- - Normalisation -------------------------------------------------------------
# Each metric has a very different value range. We normalise per-image so that
# every metric is scaled 0→1 for that image. This stops metrics with large
# absolute values from dominating, and helps the model generalise across images
# with different brightness/contrast.

def normalise_per_image(scores):
    s = scores.copy()
    s_min = s.min(axis=1, keepdims=True)
    s_max = s.max(axis=1, keepdims=True)
    s = (s - s_min) / (s_max - s_min + 1e-8) #add small epsilon to avoid division by zero
    return s

train_scores_norm = normalise_per_image(train_scores)
test_scores_norm  = normalise_per_image(test_scores)

# Convert to PyTorch tensors for use with the neural network
X_train = torch.tensor(train_scores_norm, dtype=torch.float32)
X_test  = torch.tensor(test_scores_norm,  dtype=torch.float32)

# -- - True Depth Indices for Loss Function ------------------------------------------------
# The loss function needs to know *which index* in the depths array corresponds
# to the true depth for each image (not the mm value itself).

def get_true_depth_indices(true_depths_mm, depths_array):
    indices = [np.argmin(np.abs(depths_array - td)) for td in true_depths_mm]
    return np.array(indices)

train_depth_indices = get_true_depth_indices(train_depths, data.depths)
test_depth_indices  = get_true_depth_indices(test_depths,  data.depths)

# Convert to tensor for use in loss function
train_idx_tensor = torch.tensor(train_depth_indices, dtype=torch.long)

# - - Loss Function: Margin Ranking Loss ------------------------------------------------
# We want the model to output a LOW score at the true focus depth and HIGH
# scores everywhere else. This is a ranking/ordering problem.
#
# For each image, for every depth d that is NOT the true depth, we penalise
# the model if the true depth score is not sufficiently lower than other scores.
# margin controls how much separation we demand between true and false depths.

def focus_loss(outputs, true_depth_indices, margin=0.2):
    total_loss = torch.tensor(0.0, requires_grad=True)

    for i in range(outputs.shape[0]):
        true_score = outputs[i, true_depth_indices[i]] 
        all_scores = outputs[i]                           
        penalties = torch.clamp(margin + true_score - all_scores, min=0.0)
        total_loss = total_loss + torch.mean(penalties)

    return total_loss / outputs.shape[0]

# - - - Neural Network Definition ---------------------------------------------------------------
# Simple MLP (Multi-Layer Perceptron):
#   Input:  7 metric values at a single depth
#   Output: 1 focus score for that depth
#
# The network is applied independently to each depth, then the loss is computed
# across all depths for each image. This makes the model depth-agnostic — it
# only sees the metric values, not the depth itself.

class FocusMLP(nn.Module):
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(7, 32),   
            nn.ReLU(),
            nn.Linear(32, 16),  
            nn.ReLU(),
            nn.Linear(16, 1)  
        )

    def forward(self, x):
        return self.net(x).squeeze(-1)

# - - - Training Loop ---------------------------------------------------------------

model     = FocusMLP()
optimiser = torch.optim.Adam(model.parameters(), lr=1e-3)

losses     = []

    model.train()
    optimiser.zero_grad()               

    outputs = model(X_train)           
    loss    = focus_loss(outputs, train_idx_tensor, margin=0.2)

    loss.backward()                   
    optimiser.step()                

    losses.append(loss.item())

    if epoch % 15 == 0:
        print(f"  Epoch {epoch:3d}/{num_epochs} | Loss: {loss.item():.4f}")

with torch.no_grad():
